Lab A

Build & run it locally with Podman

~10 min

Turn source code into an image, run it as a container, then bring up the full app — web + redis — with a single command.

Enter your lab host above to enable the buttons.
1

Build an image

terminal
podman build -t sandbox-app .

An image is your app, its dependencies, and how to start it — frozen into one portable artifact. The recipe is the Dockerfile.

terminal
podman images  # see the image you just made
2

Run a container from that image

terminal
podman run -d -p 8080:5000 --name web sandbox-app
podman ps  # your image is now a running container

A container is a running instance of an image. -d runs it in the background; -p 8080:5000 maps your laptop's port 8080 to the app's port 5000.

terminal
podman logs web

You'll see it complain it can't reach Redis — this app is two pieces, and one container is only one of them. That's our cue for Compose.

terminal
podman rm -f web  # clear it before the full-stack run
3

Run the whole app with Compose

terminal
podman compose up -d

docker-compose.yml describes both services and wires them on one network. One command brings up the complete app.

terminal
podman ps                 # two containers now: web and redis
curl localhost:8000       # the page renders; refresh and the counter climbs

Open http://localhost:8000 in the browser and refresh a few times.

4

Tear it down

terminal
podman compose down
✓
Checkpoint. You built an image, ran a container, and ran a multi-service app — all on your own machine.
Bridge

How does this reach a real cluster?

~1 min · talk
Your laptop the image can't cross by itself OpenShift cluster

You just built an image on this laptop. The OpenShift lab is a completely separate environment — it cannot see that image. In the real world you bridge that gap by putting the image somewhere both sides can reach: you push it to a shared registry (Quay, an internal registry…), usually from a CI/CD pipeline that builds it once and promotes it.

For this workshop we use a shortcut: OpenShift builds the image itself, from the app's source code. Great for learning — but that's the shortcut. In production you'd build once in a pipeline and ship a versioned image, not rebuild inside every cluster.

Lab B

Deploy the same app to OpenShift

~9 min

Get the app running as pods, give it a public URL, and scale it.

1

Log in to your cluster

your login command
‹paste your oc login command in the panel above›
oc whoami
oc project  # your personal namespace

The login command comes from the OpenShift console — top-right menu → Copy login command. Paste it into the panel above and it drops in here.

2

Deploy Redis first (the backing service)

terminal
oc new-app redis:alpine --name=redis

OpenShift pulls the public Redis image and creates a Deployment + Service. Redis first, so the redis name exists the moment web starts up.

3

Let OpenShift build & deploy the web app from source

terminal
oc new-app https://github.com/wlptn/podman-openshift-workshop \
  --name=web --strategy=docker

OpenShift clones the repo, builds the image in the cluster from the Dockerfile, stores it in the internal registry, and rolls out a Deployment + Service — no laptop image needed.

terminal
oc logs -f bc/web  # watch the build; Ctrl-C after "Push successful"
4

See your app running as a pod ⭐

terminal
oc get pods

web-… and redis-… both Running. This is the moment: your app is a pod on a real cluster.

5

Give it a public URL

terminal
oc create route edge web --service=web --insecure-policy=Redirect
oc get route web

A Route is the public front door. edge adds HTTPS at the router; Redirect sends http → https. Open the URL in a browser.

!
If a route ever shows “Application is not available” — it's the Route/Service layer, not your code. Usually http-vs-https or a port mismatch, not a crash.
6

Scale up and down ⭐

terminal
oc scale deployment/web --replicas=3
oc get pods -w   # watch three web pods appear; Ctrl-C to stop

Refresh the app a few times — the counter keeps climbing correctly across all 3 pods, because they share the one Redis. That's the stateless-web idea made visible.

terminal
oc scale deployment/web --replicas=1

You declare the count you want; OpenShift makes reality match. Describe the end state — the platform keeps it true.

✓
Checkpoint. Same app, now on a real cluster — deployed, exposed over HTTPS, and scaled.
Wrap-up

Why this matters

Same image, anywhere

Build once, run on a laptop or a cluster. No “works on my machine.”

Small, independent pieces

A stateless web tier plus a shared backing service is what lets you scale safely.

Declarative platform

You state the desired end state; OpenShift keeps it true — restarts, scaling, rollouts.
